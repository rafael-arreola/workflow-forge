Manual de Referencia Absoluta (DSL v1.0)

Guía de ingeniería exhaustiva para diseñar, estructurar, implementar y ejecutar workflows declarativos e híbridos de alta disponibilidad en Workflow Forge.

1. Arquitectura y Filosofía del Sistema

workflow-forge es un motor de orquestación de workflows declarativos e híbridos basado en un Grafo Dirigido Acíclico (DAG) y ejecutado de manera asíncrona sobre el runtime de Tokio en Rust. Su diseño se rige por tres principios inquebrantables:

1

Aislamiento Estricto de Datos: El flujo de datos no se manipula mediante código imperativo arbitrario; en su lugar, se gestiona a través de mappings JSONPath inmutables aplicados sobre un documento de estado compartido de forma concurrente.

2

Desacoplamiento de Carga Útil (Mecánica de Blobs): Los payloads binarios pesados (archivos CSV, audios, imágenes) nunca viajan "inline" en el JSON de contexto. En su lugar, viajan por referencia mediante identificadores hash estables basados en la especificación $blob. El ciclo de vida de estos archivos está atado a la ejecución y se recolecta automáticamente al terminar el flujo.

3

Resiliencia Defensiva Multi-Frontera: El motor encapsula fallas de red mediante políticas de reintento con exponencial backoff y jitter, y aísla pánicos de software de extensiones mediante mecanismos catch_unwind, reconduciendo la ejecución por aristas alternativas de error sin colapsar la infraestructura principal.

2. El Documento de Estado y JSONPath

El WorkflowContext mantiene en memoria el estado completo del workflow mediante un cerrojo de lectura/escritura (RwLock<serde_json::Value>). Esto permite que múltiples ramas paralelas se ejecuten de forma concurrente sin condiciones de carrera.

Anatomía del Contexto

{
  "trigger": {
    "origen": "carga_manual",
    "archivo_id": "01J0A1B2C3...UUIDv7"
  },
  "workflow": {
    "id": "wf_procesar_ventas",
    "name": "Pipeline de Ventas Diarias",
    "version": "1.0.0",
    "execution_id": "01H9Y2K3...UUIDv7",
    "parent_execution_id": null
  },
  "nodes": {}
}

El DSL de Enrutamiento de Datos

Para mapear variables dinámicas, se utiliza el motor de JSONPath con las siguientes reglas sintácticas estrictas:

  • $.trigger: Accede a los datos proporcionados durante el arranque del workflow.
  • $.nodes.<node_id>.output: Accede al resultado exitoso producido por un nodo específico que ya ha finalizado. Ejemplo: $.nodes.obtener_tasas.output.body.rates.MXN.
  • $.nodes.<node_id>.error: Accede al objeto de error estructurado generado por un nodo fallido, si y solo si la ejecución continuó a través de una arista on: error.
  • $$. (Escape): Permite introducir cadenas literales que inician con $.. Por ejemplo, "$$.propiedad" se resolverá exactamente como el string "$.propiedad" sin ser interpretado.

3. Anatomía del JSON del Workflow

Un documento de workflow es un archivo JSON/YAML autónomo. La raíz del documento permite empaquetar no solo el grafo, sino dependencias locales que garantizan la portabilidad del workflow entre entornos: 

{
  "spec": "1.0",
  "id": "mi_id_unico_opcional",
  "name": "Nombre de la Orquestación",
  "version": "1.0.0",
  "tasks": [],
  "workflows": [],
  "nodes": [],
  "edges": []
}
Clave Raíz Tipo Obligatorio Descripción Técnica
spec string Sí La versión de la especificación del esquema. Debe establecerse en "1.0".
name string Sí Identificador único del workflow. Utilizado para registros y llamadas como subworkflow.
version string Sí Versión semántica del workflow.
tasks array No Colección de perfiles de tarea locales (inline), aislando sus definiciones del registry global.
workflows array No Colección de sub-workflows inline, estructurando componentes autónomos.
nodes array Sí Grafo de nodos de procesamiento. Cada uno exige un ID y un kind único.
edges array Sí Grafo de conexiones dirigidas. Permite configurar control de errores y pánicos.

4. Nodos de Inicio y Fin (`start` / `end`)

4.1 Nodo `start`

Establece el punto de arranque del flujo y precompila validadores del trigger: 

{
  "id": "start",
  "kind": "start",
  "schema": {
    "type": "object",
    "required": ["ruta_csv"],
    "properties": { "ruta_csv": { "type": "string" } }
  },
  "defaults": { "ambiente": "produccion" }
}

4.2 Nodo `end`

Representa la terminación del flujo. Permite mapear y estructurar el output retornado al cliente: 

{
  "id": "fin_exitoso",
  "kind": "end",
  "status": "success",
  "output": {
    "registros_procesados": "$.nodes.procesar_lote.output.ok",
    "duracion_total_ms": "$.workflow.execution_id"
  },
  "schema": {
    "type": "object",
    "required": ["registros_procesados"]
  }
}

5. Nodos de Tarea (`task`)

Invocan extensiones físicas registradas o perfiles de configuración locales, proporcionando políticas de resiliencia ante errores de red o timeouts: 

{
  "id": "descargar_archivo",
  "kind": "task",
  "task": "http.request",
  "input": {
    "url": "$.trigger.ruta_csv",
    "method": "GET"
  },
  "timeout_ms": 30000,
  "retry": {
    "max": 3,
    "backoff": "exponential",
    "initial_ms": 1000
  }
}

6. Iterador Foreach

Dado que el grafo es acíclico y prohíbe bucles estáticos, para procesar colecciones masivas de datos se emplea un nodo foreach. Este utiliza procesamiento asíncrono optimizado por streams que gestiona concurrencia y rate-limits sin saturar el runtime: 

{
  "id": "procesar_lote",
  "kind": "foreach",
  "task": "http.request",
  "items": "$.nodes.obtener_usuarios.output.usuarios",
  "concurrency": 5,
  "throttle_ms": 200,
  "on_item_error": "collect"
}

7. Gateways y Sincronía

Permiten ramificar el control del flujo o unificar múltiples ramas paralelas de manera coordinada.

Gateway Exclusive (Condicional - Or-Split)

Evalúa condiciones de arriba a abajo. Dirige la ejecución únicamente por la arista ganadora: 

{
  "id": "evaluar_monto",
  "kind": "gateway",
  "gateway": "exclusive",
  "branches": [
    {
      "when": { "path": "$.nodes.obtener_datos.output.monto", "gte": 10000 },
      "edge": "ruta_alto_valor"
    },
    { "else": true, "edge": "ruta_estandar" }
  ]
}

Gateway Join (Barrera de Sincronización - And-Join)

Bloquea el progreso asíncrono y acumula en memoria las llegadas de cada rama. Se desbloquea cuando se completan todas las aristas entrantes declaradas estáticamente. Su salida consolidada contiene las salidas de cada predecesor: 

{
  "id": "unir_ramas",
  "kind": "gateway",
  "gateway": "join"
}

8. Subworkflows

Permite la jerarquía y modularidad al invocar otros workflows de forma encapsulada. Comparte dinámicamente el BlobStore de la ejecución raíz para transmitir archivos masivos eficientemente y emite telemetría vinculada mediante el campo parent_execution_id: 

{
  "id": "ejecutar_limpieza",
  "kind": "subworkflow",
  "workflow": "limpieza_temporales_s3",
  "input": { "directorio_raiz": "$.trigger.ambiente" }
}

9. Aristas y Manejo de Desastres

Las aristas conectan nodos lógicamente, pero también definen flujos alternativos ante incidentes para lograrworkflows auto-recuperables: 

[
  { "from": "start", "to": "descargar_archivo" },
  { "from": "descargar_archivo", "to": "procesar_datos" },
  { "from": "descargar_archivo", "on": "error", "to": "notificador_alerta" },
  { "from": "procesar_datos", "on": "panic", "to": "fin_catastrofico" }
]
  • on: "error" (Circuit Breaker): Si el nodo de origen falla tras todos los reintentos, el motor no detiene la ejecución; serializa el error en $.nodes.ID.error y desvía el control por esta ruta de escape.
  • on: "panic" (Aislamiento de Código): Captura pánicos de extensiones de terceros mediante catch_unwind. Los pánicos representan bugs y nunca se reintentan, derivándose forzosamente por esta arista protectora.

10. Motor de Condiciones

El motor de condiciones de gateways exclusivo evalúa un AST declarativo de condiciones en JSON. Esto garantiza seguridad de aislamiento y compilación preventiva.

Operador Tipo de Operando Descripción de la Evaluación
eq / ne Cualquier JSON Value Comprueba igualdad o desigualdad estricta de tipos y valores.
gt / gte / lt / lte Número o String Menor/mayor estricto o igual (numérico de punto flotante o lexicográfico).
in Array de JSON Values Comprueba si el valor del path está en la lista.
contains Cualquier JSON Value Si el valor es un array, busca pertenencia. Si es un string, busca subcadena.
exists / is_null Booleano Comprueba si el path dinámico resuelve o si el valor resuelto es explícitamente nulo.
starts_with / ends_with String Comprueba coincidencia en los límites de la cadena de caracteres.
matches String Cumplimiento de Expresión Regular (compiladas mediante caché global de procesos).

11. Perfiles de Tarea y Secretos

Un perfil (TaskProfile) crea una tarea virtual encapsulando credenciales y bindeos. Al registrarse, se interceptan las llaves {"$secret": "KEY"} y se resuelven en memoria utilizando el SecretProvider. Las credenciales sensibles jamás se guardan en el archivo de flujo ni se exponen en telemetría. 

{
  "tasks": [
    {
      "id": "sendgrid.enviar_correo",
      "extends": "http.request",
      "bind": {
        "url": "https://api.sendgrid.com/v3/mail/send",
        "method": "POST",
        "auth": {
          "type": "bearer",
          "token": { "$secret": "SENDGRID_API_KEY" }
        },
        "body": {
          "subject": "@.asunto",
          "content": [{ "type": "text/plain", "value": "@.mensaje" }]
        }
      },
      "output": "@.body"
    }
  ]
}

Parte III: Catálogo Técnico de Extensiones

Esquemas técnicos, parámetros y variables admitidas por las extensiones de la biblioteca.

namespace

`data.*` — Manipulación de Datos

data.transform

Aplica un shape de transformación usando JSONPaths locales (prefijo @) relativos al input para reestructurar objetos de manera flexible.

data.map

Transforms a collection of JSON items, applying a custom shape template individually to every element in the array.

data.merge

Realiza un deep-merge de estructuras. Especialmente útil después de un nodo join para unificar ramas paralelas.

data.template

Motor de reemplazo de strings (ej. Hola ${$.trigger.nombre}, tu id es ${$.trigger.id}).

data.cast

Sanea, formatea y normaliza tipos de datos (Conversión a Fechas ISO, normalización de decimales/miles, textos trim/upper/lower, y políticas on_invalid).

namespace

`http.*` — Conectividad de Red

http.request

Cliente HTTP asíncrono basado en reqwest. Soporta streaming nativo; puede transmitir y recibir archivos binarios gigantes vinculándolos a las referencias dinámicas de tipo {"$blob": "..."} del context, permitiendo transferencias masivas sin sobrecargar la memoria RAM.

Campo del Input Tipo Obligatorio Descripción
url string Sí Dirección URI de destino.
method string No Método HTTP. Opciones: "GET", "POST", "PUT", "PATCH", "DELETE". Por defecto: "GET".
headers object No Pares clave-valor de cabeceras HTTP personalizadas.
auth object No Credenciales de autenticación. Admite: Basic o Bearer.
fail_on_error_status boolean No Si es true, respuestas 4xx o 5xx disparan fallas y reintentos. Por defecto: false.
response_body string No Formato de respuesta: "auto", "text" o "blob" (streaming de descarga directa a almacenamiento).
body | form | text | body_blob | multipart varios No Mutuamente Excluyentes. Define el cuerpo: JSON, formulario codificado, texto plano, streaming de archivo pesado (body_blob), o matriz multipart.

12. Guía de Integración Programática (Rust)

Para compilar, validar y ejecutar workflows dentro de tu anfitrión de Rust, utiliza el siguiente patrón de integración: 

use std::sync::Arc;
use serde_json::json;
use workflow_forge_core::workflow::WorkflowDefinition;
use workflow_forge_core::executor::WorkflowExecutor;
use workflow_forge_core::registry::TaskRegistry;
use workflow_forge_core::secret::EnvSecrets;
use workflow_forge_core::task::WorkflowData;
use workflow_forge_core::observe::InMemoryHistory;

#[tokio::main]
async fn main() -> Result<(), Box> {
    // 1. Cargar definición
    let workflow_json = json!({
        "spec": "1.0",
        "name": "flujo_produccion",
        "version": "1.0.0",
        "nodes": [
            { "id": "start", "kind": "start" },
            { "id": "end", "kind": "end" }
        ],
        "edges": [{ "from": "start", "to": "end" }]
    });
    let definition: WorkflowDefinition = serde_json::from_value(workflow_json)?;

    // 2. Preparar el TaskRegistry y secretos
    let registry = Arc::new(TaskRegistry::new());
    let secrets = EnvSecrets::default();

    // 3. Construir y validar el Executor (Compila esquemas y busca ciclos)
    let executor = WorkflowExecutor::builder(definition)
        .registry(registry)
        .secrets(&secrets)
        .build()
        .map_err(|errors| errors.into_iter().next().unwrap())?;

    // 4. Inyectar telemetría e iniciar ejecución asíncrona
    let history = Arc::new(InMemoryHistory::new());
    let executor = executor.with_observer(Arc::clone(&history) as Arc);

    let result = executor.run(WorkflowData(json!({ "tenant_id": "usr_99" }))).await?;
    println!("Workflow finalizado con éxito: {}", serde_json::to_string(&result.0)?);

    Ok(())
}

13. Resolución de Problemas y Códigos de Error

El motor implementa validación estructural y aserciones en runtime robustas para levantar códigos de error auto-explicativos:

Códigos de Validación (Fase de Construcción)

  • UNSUPPORTED_SPEC / DUPLICATE_NODE_ID La versión spec es inválida o existen nodos con identificadores duplicados en el JSON.
  • UNKNOWN_NODE_REF / NO_START_NODE / NO_END_NODE Una arista referencia un nodo inexistente, o el grafo carece de un nodo de inicio/fin.
  • GATEWAY_BRANCH_WITHOUT_EDGE / GATEWAY_EDGE_WITHOUT_BRANCH Desconexión lógica en un gateway exclusive entre sus ramas y las etiquetas de aristas adyacentes.
  • SUBWORKFLOW_CYCLE / SUBWORKFLOW_DEPTH_EXCEEDED Llamadas recursivas infinitas entre subworkflows o profundidad de anidación mayor a 5 niveles.
  • CYCLE_DETECTED / UNREACHABLE_NODE El grafo contiene ciclos (Kahn check) o existen nodos huérfanos que no se pueden conectar desde el start.

Códigos de Ejecución (Fase de Runtime)

  • MAPPING_PATH_NOT_FOUND / INVALID_JSONPATH El JSONPath de mapping no resuelve ningún valor dinámico en el estado o tiene errores de sintaxis.
  • TASK_INPUT_INVALID / TASK_OUTPUT_INVALID Los payloads dinámicos violan el JSON Schema de entrada o salida registrado en el manifiesto de la tarea.
  • TASK_TIMEOUT / TASK_PANIC La ejecución de la tarea superó el tiempo máximo absoluto, o el código interno Rust sufrió un pánico severo.
  • JOIN_INCOMPLETE Falla de diseño: El flujo finalizó pero quedaron gateways de tipo join esperando ramas que nunca llegaron debido a un desvío exclusive.
  • PROFILE_BIND_INVALID / SECRET_NOT_FOUND El bindeo pre-configurado produce un JSON que la tarea base de origen de la extensión rechaza, o el secreto no está disponible en la infraestructura.
