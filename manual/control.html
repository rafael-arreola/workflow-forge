Decisiones y flujos avanzados

Usa instrucciones estructuradas para expresar alternativas, concurrencia y repetición sin crear aristas ambiguas.

El cuerpo como unidad de coordinación

Un cuerpo tiene entry, nodes, edges y output. Es un subgrafo inline; no tiene una revisión independiente. Los ejemplos de esta página son nodos para insertar en un documento. Sus documentos completos y host están incluidos y verifican el resultado esperado.

No conviertas cada control en una operación

Una extensión implementa actividades de negocio. Decision, try, parallel, foreach, loop, subworkflow, timer y await_signal pertenecen al lenguaje del coordinador y conservan sus garantías de estado.

Decision: elegir un solo camino

Se evalúan los casos en orden y se ejecuta el primero verdadero. La salida será {"selected":"si","output":"continuar"} o {"selected":"no","output":"revisar"}. Sin coincidencia ni fallback se produce control.no_match. La condición debe ser boolean, no "true".

Elegir la política de errores del grupo

PolíticaComportamiento
fail_fastTras un fallo conocido, deja de admitir hijos y cancela cooperativamente los activos; espera su clasificación.
collectReúne éxitos y errores conocidos para permitir que el workflow decida qué hacer con el conjunto.
Efecto inciertoNo se convierte en un error ordinario recolectable. El grupo/run queda bloqueado hasta resolverlo; collect puede dejar avanzar hijos independientes.

El presupuesto global de intentos concurrentes también limita las operaciones. Subir la concurrencia de un nodo no amplía las cuotas del host.

Loop: mantener y reemplazar un estado

El ejemplo recibe {"continuar":true,"valor":"inicial"} y devuelve {"continuar":false,"valor":"terminado"}. La condición y el cuerpo leen un sobre con state e iteration. El output del cuerpo reemplaza el estado completo.

Aquí la operación entrega un estado fijo para mostrar el mecanismo. En una integración, una operación calcularía el siguiente cursor/estado. El engine no evalúa expresiones aritméticas embebidas en una string.

Se comprueba la condición antes de cada vuelta. Si sigue verdadera al llegar a max_iterations, on_limit: "fail" falla y "return_last" devuelve el último estado. Documento completo.

Subworkflow: reutilizar una definición

El hijo tiene ámbito e identidad propios dentro del run raíz. No es un proceso remoto ni un nuevo run independiente. Los ciclos de referencias y las revisiones ausentes se rechazan al preparar. Documento completo.

Timer y esperas externas

El timer confirma una fecha absoluta y conserva su input como output. Un reinicio durable no reinicia el contador. La cancelación y el deadline del run siguen vigentes.

Para una aprobación o trabajo externo usa await_signal, explicado en señales. Evita una operación que espere indefinidamente haciendo polling.

Rutas por resultados y errores

Usa forge.data.equals para comparar {left, right} y alimentar un decision. Un try envuelve una operación o un cuerpo completo: ejecuta un handler por código o su fallback obligatorio. Ver manejo de errores.
