Guía de lectura · Capítulo 00

Inicio y ruta de aprendizaje

Aprende a integrar Workflow Forge dentro de tu aplicación Rust, registrar capacidades y ejecutar workflows declarativos.

El punto de partida es una librería

Tu aplicación conserva una instancia del motor y comparte su handle. La librería no levanta servicios ni incluye un cliente remoto. El host controla ejecución, cancelación y cierre.

Diagramas para acompañar la lectura

Los capítulos incluyen una vista del diagrama y un enlace al visor interactivo de Archify para ampliar y explorar las relaciones.

  • Arquitectura embebida: Qué vive dentro de tu aplicación.
  • Arranque y cierre: Cómo crear y conservar una instancia.
  • Módulos virtuales: Del contrato a una capacidad registrada.
  • Workflows y datos: Cómo se conectan los valores del ejemplo de saludo.
  • Comunicación entre procesos: Cómo reservar una espera y entregar una señal.

El contenido de los diagramas está en español. Los controles del visor y su atributo de idioma usan el inglés predeterminado de Archify. Las vistas SVG del manual se pueden leer sin JavaScript.

Aplicarlo en tu sistema

Abrir las ocho recetas de integración: una llamada, una fachada compartida, cancelación, módulos propios, rutas por resultados, importación compuesta, archivos y recibos/señales. Cada receta enlaza código completo y muestra qué entrada recibe y qué devuelve.

Qué vas a construir

Un primer workflow limpiará el texto " Rafael ". Después crearás una operación de saludo, conectarás sus datos y avanzarás a lotes, decisiones, artefactos, SQLite y señales.

EtapaLecturaAl terminar podrás
1 · Primer usoIntegración y arquitecturaArrancar una instancia, ejecutar un workflow y cerrarla correctamente.
2 · Capacidades propiasMódulos, workflows y datosPublicar operaciones con contratos y conectar sus entradas y salidas.
3 · CoordinaciónControles y recursosProcesar lotes, reutilizar subworkflows y usar archivos o APIs.
4 · Operación confiablePersistencia, efectos, procesos y operaciónRecuperar trabajo, gestionar incertidumbre y diagnosticar límites.

Preparación

  • Conocimientos básicos de Rust, async/await, Cargo y JSON.
  • Rust 1.98.1, fijado por el repositorio, y el checkout de Workflow Forge. El proyecto aún no tiene una versión pública que este manual indique instalar desde crates.io.
  • Un runtime Tokio en la aplicación que integra el motor. Los ejemplos completos usan #[tokio::main].
  • Internet para cargar los estilos y los diagramas Mermaid por CDN; sus descripciones permanecen legibles si el diagrama no carga. Las páginas y sus ejemplos están en archivos locales; no requieren una compilación frontend.

Abre manual/index.html directamente en el navegador. También puedes servir la raíz del repositorio:

Después abre http://127.0.0.1:8090/manual/. Este servidor solo entrega documentación; no ejecuta el motor.

Ejemplos descargables y verificables

El proyecto manual/ejemplos es un workspace de demostración independiente y usa los crates locales. Incluye Cargo.lock. Sus features habilitan SQLite y conectores para cubrir el recorrido completo del manual; el primer ejemplo solo usa memoria.

ProgramaQué enseña
inicioEntrada → normalización → resultado; cierre ante error.
modulosRegistro de una extensión y dos nodos conectados.

sistemaFachada de aplicación, plan compartido y concurrencia acotada.

respuestas200, 404, 429, otro status y campo ausente; rutas y catch.

Salida esperada: "Rafael". Los bloques marcados Fragmento se insertan en el contexto indicado; los archivos descargables son programas completos.

Alcance de esta entrega

  • Los plugins son Rust compilado y confiable dentro del proceso. No hay carga de DLL/WASM ni aislamiento de código de terceros.
  • SQLite es local y tiene un coordinador propietario. No es un motor de workers distribuidos ni admite varios hosts escribiendo esa misma instancia.
  • El engine funciona sin interfaz gráfica. El catálogo y la metadata de presentación permiten construir un editor por separado.
  • La validación del motor usa casos de referencia y casos borde. Las integraciones reales y sus objetivos de producción se validan cuando el implementador decida conectarlas.
