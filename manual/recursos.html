Secretos, archivos y conectores

Inyecta infraestructura desde el host y entrega a cada operación únicamente los recursos que declara.

Secretos fuera del workflow

No guardes tokens dentro de config, input, presentation o mensajes de error. El host registra un proveedor; el descriptor solicita el recurso lógico secret:nombre.

La operación declara "secret:crm" en required_resources y obtiene el secreto con context.secret("crm").await. El acceso del run también debe conceder ese recurso. Para integrar una bóveda, implementa SecretProvider y sustituye el proveedor en el builder.

Artefactos: publicar bytes y vincularlos al run

Los archivos se transportan como ByteStream y se identifican mediante ArtifactRef. Este fragmento muestra una carga pequeña; para archivos grandes entrega chunks desde tu origen sin construir todo el archivo en memoria.

La lista options.artifacts vincula la referencia al run aceptado. Los bytes se obtienen después con read_artifact; no se inventa una ruta desde el ID. El host necesita permiso Start para publicar, Read para leer y el grant artifacts.

Programa completo con lectura acotada · Workflow que transporta la referencia

Dentro de una operación usa context.write_artifact y context.read_artifact; el descriptor debe declarar artifacts. En SQLite instala el mismo proveedor coordinado para ejecuciones y artefactos. No pegues una referencia de otra instancia esperando que los bytes existan allí.

Conectar una API desde la librería

Requiere la feature integrations. Este es un cliente saliente usado por una operación; no necesita levantar el servicio HTTP de Workflow Forge.

La URL es ilustrativa: sustitúyela por tu destino. El perfil fija URL y método; el input solo aporta query y, en escrituras, body. La revisión se deriva del perfil. Cambiarlo cambia la revisión que debe usar el workflow.

El módulo desactiva redirects y retries internos. GET se clasifica Read/Safe; las escrituras HTTP genéricas son Write/Unsafe. Un timeout después de despachar una escritura puede dejar un efecto incierto.

Archivos y CSV

El lector recibe {"path":"clientes.csv"} relativo a la raíz y devuelve una referencia de artefacto. El parser CSV recibe {"source":<referencia>,"offset":0,"size":100}.

El resultado CSV contiene headers, rows y next_offset. Cada fila incluye index, line, fields y valid_columns. Termina cuando next_offset sea null. El módulo no interpreta SKU, fechas ni reglas del negocio: agrega una operación propia para esas decisiones.

Lotes acotados

El parser actual vuelve a leer y analizar la fuente acotada en cada lote. Paginación no significa memoria constante para archivos ilimitados. Configura el tamaño máximo de archivo, lote, campos y resultados.

Sustituir infraestructura

PuertoResponsabilidad
ExecutionStorePropiedad, aceptación, revisiones/CAS, recuperación, deduplicación y retención.
ArtifactStoreStreams, publicación, lectura, referencias y coordinación con runs.
SecretProviderResolución de secretos autorizados por scope y nombre.
ExecutionObserverRecepción de eventos; no controla transiciones ni sustituye auditoría durable.
BackoffPolicyDemora tras autorizar el retry; no decide certeza ni repetibilidad.

Un proveedor nuevo necesita conformidad del contrato y pruebas específicas de concurrencia/caídas para las garantías que anuncie. El kit conformance es una ayuda secuencial, no una certificación completa de durabilidad.
