Mover y transformar datos

Usa bindings explícitos para construir entradas, seleccionar resultados y pasar contexto entre ámbitos.

Las cuatro formas de binding

FormaQué haceEjemplo
literalEntrega un valor JSON tal como está.{"literal":42}
selectLee un valor de input o de un nodo precedente.{"select":{"source":"input","pointer":"/cliente/id"}}
objectConstruye un objeto evaluando un binding por propiedad.{"object":{"activo":{"literal":true}}}
arrayConstruye un array con bindings.{"array":[{"literal":"A"},{"literal":"B"}]}

Una string que parece una expresión, como "$.cliente", sigue siendo una string literal. No hay eval, templates ni JSONPath implícito. Transformaciones, cálculos y conversiones van en operaciones con contratos.

Si apodo no existe, se usa "Invitado". Si existe y vale null, se conserva null: el fallback no reemplaza valores presentes ni repara un tipo inválido. Sin fallback, una ruta ausente produce mapping.missing.

Pasar datos a controles y subworkflows

Dentro de…Qué significa inputCómo leer resultados desde el padre
Cuerpo normalInput del workflow o del cuerpo actual.El binding output publica el resultado de ese cuerpo.
Rama de parallel / decisionInput del nodo de control.Leer el resultado reunido del nodo de control, no un nodo interno.
Cuerpo de foreachObjeto con item, index y context.Array ordenado por índice con status y output/error.
Cuerpo y condición de loopObjeto con state e iteration.El nodo loop publica el estado final.
SubworkflowInput construido por el nodo subworkflow.El output del hijo se convierte en output de ese nodo.

El padre debe haber incluido pedido en el input del foreach. Los cuerpos no leen variables del padre ni outputs de otra rama de forma implícita.

De una ejecución a otra

Aquí el host coordina dos runs independientes. No hay una transacción automática entre terminar A e iniciar B. Para una misma unidad de trabajo recuperable, considera un subworkflow dentro del run raíz. Para mover datos a otro proceso, usa un adaptador explícito descrito en comunicación entre procesos.

Bytes grandes: usa artefactos

Un PDF, CSV o archivo binario no tiene que convertirse en un JSON enorme ni en base64. Publica sus bytes como stream y pasa un ArtifactRef. La referencia describe identidad, scope, tamaño y media type; no contiene una ruta de disco.

El capítulo de artefactos muestra cómo adjuntarlo al run. Poner un objeto con forma de referencia dentro del input no sustituye esa vinculación explícita.
